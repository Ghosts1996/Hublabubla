# Умный импорт: контракт интеграции

## Текущее состояние

Клиент классифицирует официальные ссылки и умеет создавать задание, опрашивать прогресс и сохранять доступные аудиозаписи в локальное избранное. Backend и доступ к каталогам провайдеров не развёрнуты. Без конфигурации интерфейс только проверяет ссылку.

Перед app.js интегратор может установить:

```js
window.VIBE_CONFIG = {
  importBackendUrl: 'https://api.example.com',
  getAccessToken: async () => /* пользовательская сессия */ null
};
```

Токены провайдеров никогда не помещать в APK. Приложение использует только пользовательскую сессию backend. Не добавлять конфигурацию с секретами в Git. Backend обязан проверять пользователя, владельца задания и права на аудиозаписи. Его CORS должен явно разрешать origin приложения (Capacitor: https://localhost).

## API

`POST /api/v1/import-jobs`

```json
{"url":"https://open.spotify.com/playlist/abc","target":"favorites"}
```

Ответ:

```json
{"data":{"job_id":"imp_123","status":"queued"}}
```

`GET /api/v1/import-jobs/imp_123`

```json
{"data":{"job_id":"imp_123","status":"completed","total":1,"processed":1,"items":[{"title":"Название","artist":"Исполнитель","status":"added","canonical_track_id":"track_123","audio_url":"https://example.com/authorized.mp3"}]}}
```

Статусы задания: queued, resolving, matching, saving, completed, partially_completed, failed, cancelled.
Статусы позиции: added, already_exists, missing, unavailable, failed.

audio_url может отсутствовать: такие позиции отображаются для ручной проверки, но не объявляются воспроизводимыми. URL должен быть разрешённым HTTPS-аудиофайлом; запрещено обходить DRM или скачивание провайдера. Временные подписанные URL нельзя считать долговременными ссылками медиатеки: production-backend должен выдавать обновляемую playback-reference через отдельный endpoint.

## Поток сервера

1. Проверка OAuth-сессии и лимитов пользователя.
2. Классификация URL по точному allowlist хостов/форматов.
3. Получение всех страниц треклиста официальным адаптером; unsupported capability возвращает явную ошибку.
4. Нормализация без удаления смысловых версий записей (remix/live/edit).
5. Дедупликация по валидному ISRC либо artist/title/version/duration.
6. Ограниченный worker pool, таймауты, rate-limit backoff и поиск через разрешённые источники.
7. Matcher проверяет версии, исполнителей, длительность и право воспроизведения.
8. Идемпотентная транзакция: unique(user_id, canonical_track_id) для избранного.
9. Сохранение задания и результатов в постоянную БД.

Остановка ожидания на клиенте НЕ отменяет серверное задание. Повторное нажатие создаёт новое задание; до production необходимо добавить idempotency-key, восстановление job_id после перезапуска и endpoint отмены. Сейчас этот слой не предназначен для массового публичного запуска.
